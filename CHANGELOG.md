# Changelog

All notable changes to Trellis are recorded in this file. The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html). Before 1.0, a minor release may break the API, with migration notes (plan §10).

Each user-visible change adds a line under "Unreleased", in the group that fits: Added, Changed, Deprecated, Removed, Fixed or Security. A release renames "Unreleased" to its version and date, and starts a new, empty one.

## [Unreleased]

Phase 0 (foundations) is complete. The injector API is being built for v0.1: bindings, modules, lifetimes, creating objects (`create<T>()`) and its diagnostics with the path from the root, and test overrides work; packaging comes next.

### Added

- **Package:** the header-only CMake target `trellis::trellis`, with install rules and `find_package(trellis CONFIG)`. `<trellis/trellis.hpp>` is the umbrella header. `<trellis/config.hpp>` holds the version (0.1.0, in development) and the `TRELLIS_HAS_*` macros that detect C++23 and C++26 features. Licensed under the Boost Software License 1.0.
- **Meta toolkit** (`include/trellis/meta/`, T1.1): `trellis::fixed_string<N>`, a string usable as a template argument and as a compile-time message buffer; `trellis::type_name<T>()`, a type's name as a constant expression, with member pointer types named the same on every compiler; and `trellis::result<T>`, which is `std::expected<T, trellis::failure>` where the standard library provides it (`__cpp_lib_expected`) and otherwise a fallback with the same core interface, with `trellis::make_unexpected` to return a failure in both. Internally, type lists and an inheritance-based type map whose lookups never recurse, fold over a pack or instantiate the types they hold ([notes](docs/internals/meta-toolkit.md)).
- **Configuration macros** in `<trellis/config.hpp>`: `TRELLIS_HAS_EXCEPTIONS`, `TRELLIS_HAS_TYPE_PACK_ELEMENT`, `TRELLIS_IS_SAME` (the `__is_same` builtin where there is one), and `TRELLIS_FUNCTION_SIGNATURE` with `TRELLIS_FUNCTION_SIGNATURE_CLASS_KEYS` and `TRELLIS_TYPE_NAME_RESPELLS_MEMBER_POINTERS` (MSVC and Clang 21, whose signatures misspell member pointer types).
- **Explicit constructor declarations** (`<trellis/discovery/ctor_traits.hpp>`, T1.2): `trellis::ctor<Args...>` lists the parameter types of the constructor that Trellis calls. A class declares it with a specialization of `trellis::ctor_traits<T>`, which leaves the class untouched, or with a public member alias `using trellis_ctor = trellis::ctor<...>;`. The specialization wins when both exist. A declaration that matches no constructor, or that doesn't brace-initialize an aggregate, fails to compile with [TRL-E002](docs/errors/TRL-E002.md), the first error ID that the library emits.
- **Deduced constructor discovery** (`<trellis/discovery/deduced.hpp>`, T1.3): a class that declares no constructor has it deduced, without macros or changes to the class, for every parameter form in [docs/internals/deduction.md](docs/internals/deduction.md). Tested with GCC 13 and 14, Clang 18 and 20, and Clang 18 with libc++ on every push, and with Apple clang 21 and MSVC 19.51 in CI's weekly or on-demand runs. Parameters of type `X&&` are the request `X`; `std::optional`, `std::tuple` and `std::any` parameters need a declaration. A constructor template or variadic constructor that accepts anything, an aggregate with an array member, or an aggregate member that can't be deduced fails with [TRL-E004](docs/errors/TRL-E004.md); a constructor with more parameters than `max_ctor_arity` (16 by default) with [TRL-E010](docs/errors/TRL-E010.md); and a class with no usable constructor, such as a private one or two with the same number of parameters, or a class not yet defined, with [TRL-E002](docs/errors/TRL-E002.md). The injector that uses it comes with v0.1.
- **Configuration macros** for deduction's compiler workarounds in `<trellis/config.hpp>`: `TRELLIS_PROBE_DECLARES_TWINS` (GCC before 14), `TRELLIS_PLACEHOLDER_CONVERSIONS_BEGIN` and `_END` (GCC's `-Wconversion`), and `TRELLIS_REPEAT_THROUGH_CLASS` and `TRELLIS_ARRAY_CHECK_WITH_BRACES` (MSVC).
- **Bindings, modules and options** (`include/trellis/dsl/` and `include/trellis/static/`, T1.4; plan §6.1, §6.2, §6.9, §6.13):
  - `trellis::bind<I>` with `.to<C>()`, `.in(lifetime)` and `.allow_copy()`, or `.to_ref(x)`, `.to_ptr(p)`, `.to_value(v)` and `.to_shared(sp)`. Each step returns one binding type; nothing accumulates.
  - The lifetimes `trellis::unique` (the default), `trellis::singleton` and `trellis::singleton_inline`.
  - `trellis::make_module(...)`, which flattens bindings and modules into one module. A struct derived from a module is a module, which gives the injector a short type name.
  - `trellis::options`, a template argument with designated initializers: `strict`, `eager`, `threading`, `max_ctor_arity` and `cycle_check`. Each field takes effect with the task that implements it.
  - `trellis::make_injector<options{...}>(...)`, which flattens its arguments once into one binding map. A key bound twice is the compile error TRL-E003.
  - The request-form table of plan §6.3 is checked at compile time: a form that the binding's lifetime rejects is TRL-E005, and an unbound type requested by reference, pointer or `shared_ptr` is TRL-E012. `create<T>()` (T1.5) triggers the check.
- **Creating objects** (`injector.create<T>()`, T1.5; plan §5.3, §6.3, §7.5 to §7.7):
  - `create<T>()` builds or finds the object for any request form the binding's lifetime allows: `T`, `T&`, `const T&`, `T*`, `const T*`, `std::unique_ptr<T>`, `std::shared_ptr<T>` and `std::weak_ptr<T>`, with `.allow_copy()` making copies of shared objects. Constructor parameters are requests too, served the same way, through deduced or declared constructors. A type without a binding is built as a new object (`int` and other non-class types need a binding). It returns a prvalue for a by-value request, so a class that can't be copied or moved can be created.
  - Each injector owns its singletons: `trellis::singleton` in a `std::shared_ptr` made with one allocation, so a `std::shared_ptr` request shares real ownership (and `std::enable_shared_from_this` works), and `trellis::singleton_inline` inside the injector, with no heap allocation. The injector destroys them in reverse order of construction.
  - A singleton is built once, even when threads request it at the same time (`threading::safe`, the default), with a plain flag under `threading::none`. A constructor that throws leaves the singleton to be built by the next request; objects already built stay built.
  - `options{.eager = true}` builds every singleton in `make_injector`, which then gives the strong guarantee, and later reads need no check. `options{.strict = true}` requires a binding for every type the injector creates: an unbound type requested by value or as `std::unique_ptr` is then [TRL-E013](docs/errors/TRL-E013.md). `options{.max_ctor_arity}` bounds deduced discovery, at most 32.
  - `std::unique_ptr<I>` of a binding whose implementation derives from `I` needs `I`'s destructor to be virtual; otherwise it would delete the implementation through `I`, and the request is [TRL-E014](docs/errors/TRL-E014.md). `std::shared_ptr<I>`, singletons and by-value requests destroy the implementation itself. A binding of an object whose type is only declared, made with `.to_ptr()` or `.to_ref()`, serves its reference and pointer requests; a by-value request of it is TRL-E002.
  - The whole graph is checked at compile time, and a graph that can't be built instantiates no creation code: each failing request is one error, [TRL-E001](docs/errors/TRL-E001.md) (no binding for an abstract type, now emitted), TRL-E002, TRL-E004, TRL-E005, TRL-E010, TRL-E012, TRL-E013 or TRL-E014 (the last two provisional IDs), also for a by-value request of an abstract class and for a class that is only declared; T1.6 adds the path from the root (below). Dependency chains of 295 hops compile at GCC's default template depth, and 252 at Clang's.
  - Tested with GCC 13 and 14, Clang 18 and 20, and Clang 18 with libc++, also under AddressSanitizer, UndefinedBehaviorSanitizer and ThreadSanitizer, and without exceptions or RTTI. The research scenario wired with Trellis behaves like the hand-wired version object by object.
- **Diagnostics with the path from the root** (T1.6; plan §7.8, ADR-0006): when `create<T>()`, or `make_injector` with `options{.eager = true}`, can't build the graph, the explain pass follows the first failing request from the root down, through declared and deduced constructors, and reports its cause once. The error type names the type and the request form, the message starts with the `TRL-` ID, and an instantiation note below it (Clang's second, GCC's first "required from" line) names the path from the root, such as `trellis::error::path<App, Service>`, and the failing parameter's index. A request that several roots or consumers fail on is one error, and so are several forms of one missing binding under one root. Each deduced class on the path costs the output about a line, so a chain of 21 classes stays within 33 lines on GCC 13 and 14 and Clang 18 and 20 (NFR-07's 40), also behind four headers or with the call over three lines; a chain whose requests alternate between by value and by reference still reaches the compilers' backtrace limit, at up to 41 lines on Clang and 48 on GCC 14 in the layouts measured. A dependency cycle gets the compiler's own errors and nothing more (ADR-0014). Every TRL error is now reported from `<trellis/diagnostics/errors.hpp>`, whose instantiation note also names the error type for MSVC, which doesn't print a failed assertion's condition. [TRL-E009](docs/errors/TRL-E009.md), an override without an existing binding, has its error type and report, for `trellis::override<K>` (T1.7). Golden tests compare the output with snapshots on all four compilers.
- **Test overrides and testing helpers** (T1.7; plan §6.10):
  - `trellis::override<K>`, with `bind<K>`'s vocabulary (`.to<C>()`, `.in(lifetime)`, `.allow_copy()`, `.to_ref(x)`, `.to_ptr(p)`, `.to_value(v)`, `.to_shared(sp)`), passed to `make_injector`, replaces the binding of `K` that the other arguments provide, wherever it is among them, modules and named modules included, and keeps its place. Two overrides of one key are [TRL-E003](docs/errors/TRL-E003.md), and an override whose key nothing else binds is [TRL-E009](docs/errors/TRL-E009.md), one error per such override; the injector then reports nothing more. `make_module` rejects overrides.
  - `<trellis/testing/wiring.hpp>`, which tests include themselves: `trellis::testing::wireable<Injector, Root>`, a concept that is true exactly when `make_injector` makes an injector of that type and `injector.create<Root>()` compiles, and never reports an error, for `static_assert`s on a composition root; and `trellis::testing::create_all(injector)`, which builds every singleton through `create<Key&>()` and stops at the first constructor that throws.
  - Each injector owns its singletons, so tests that make injectors from the same module share nothing. A gMock example test puts a `StrictMock` repository in the production wiring with `override<IRepository>.to_ref(repo)`.
- **Example:** [`examples/hello_world.cpp`](examples/hello_world.cpp), plan §6.1's hello world, built and run by the tests and shown in the README.
- **Configuration macros** for the injector's storage in `<trellis/config.hpp>`: `TRELLIS_IS_CONSTRUCTIBLE` (the `__is_constructible` builtin where there is one), `TRELLIS_HAS_ATOMIC_WAIT` (which a build may set to 0 to use the fallback of a mutex and a condition variable per injector), `TRELLIS_CPU_RELAX`, `TRELLIS_NOINLINE`, `TRELLIS_COLD`, and `TRELLIS_NO_UNIQUE_ADDRESS` with `TRELLIS_EMPTY_BASES`, which keep empty bindings and slots at no size on MSVC too.
- **C++20 module and single header** (T1.8; plan §10, ADR-0008):
  - `import trellis;` with the module in `modules/trellis.cppm`, and `import trellis.testing;` for the testing helpers: the CMake target `trellis::module`, built when `TRELLIS_ENABLE_MODULE` is on. `create<T>()`, overrides and the testing helpers work through the import. It needs CMake 3.28, Ninja, and Clang 16 or later with `clang-scan-deps`; it is tested with Clang 18 and 20, and any other compiler gets a configure-time warning. GCC 14 can't use it, so CMake refuses GCC before 15. An importer gets no macros and no standard library: include `<trellis/config.hpp>` for `TRELLIS_VERSION` and the `TRELLIS_HAS_*` macros, and the standard headers you use, all before the import. A configuration macro such as `TRELLIS_HAS_ATOMIC_WAIT` is set on the module's own build. A check keeps the module's exports equal to the public names of the headers, and the unit tests that use only public names also run through the module.
  - `tools/amalgamate.py` generates the single header `single_include/trellis.hpp` (not in the repository; releases will attach it), and `--check` checks that it generates, compiles on its own and isn't stale. The unit tests run against it too (`ctest -L single_header`).
- **Compilers:** GCC 13 and 14, Clang 18 and 20, and Clang 18 with libc++ 18, built and tested on every push; Apple Clang and MSVC, built and tested weekly and on demand. All warning-free under `-Werror` or `/WX`.
- **Build presets and scripts:** CMake presets for each compiler in debug mode, two release builds, ASan with UBSan, TSan and a `-ftime-trace` build. `scripts/init.sh`, `check-fast.sh`, `check-full.sh` and `tidy.sh` print a short summary and keep the full logs in `build/logs/`; `scripts/ci-status.sh` shows the latest CI runs and the first errors of failed jobs.
- **CI:** six Linux presets on every push, TSan and the quick compile-time benchmark nightly, and macOS and Windows weekly or on demand. A failed scheduled run opens an issue.
- **Test tooling:** unit tests with GoogleTest and gMock; a check that every public header compiles on its own; compile-fail tests, which check the error ID on the first error line, regexes and a line budget (`tools/compile_fail.py`); golden diagnostics, compared after normalizing paths and compiler noise (`tools/golden.py`); and property tests that check object sharing on random dependency graphs against a model.
- **Benchmark harness:** a deterministic graph generator, compile-time runs that check the budgets of NFR-03 to NFR-05 against hand-written wiring (`scripts/bench-compile.sh`), and runtime benchmarks of the research scenario with Google Benchmark (`scripts/bench-runtime.sh`).
- **v0.1 measured against hand-written wiring** (T1.9): Trellis is now a variant of the scenario program, the generated graphs and the runtime benchmark, and `scripts/bench-compile.sh` checks it against the budgets by default. The property tests wire every random graph with Trellis too, and 200 graphs share objects exactly as the model and the hand-written wiring do. The results are in [`docs/benchmarks/v0.1.md`](docs/benchmarks/v0.1.md). Resolving the scenario's root takes 1.01 to 1.07 times as long as the hand-written wiring (target 1.1×). This first measurement missed three targets, which T1.14 took on (next line): the 100-component graph compiled 1.7 to 1.8 times as slowly (target 1.3×), the scenario's binary was 12 KiB larger on Clang (target 8 KB), and the scenario's extra compile time on Clang was +0.31 s (target +0.3 s).
- **Less code per singleton** (T1.14): a program compiles the thread-safe slot's state machine once rather than once per singleton, a singleton's `std::shared_ptr` shares one control block type with every class of its size (a class with `std::enable_shared_from_this` keeps its own), and building and storing a singleton is one function. Behaviour and slot sizes are unchanged, and no dependency chain needs more template depth. Measured on a quiet machine, the 100-component graph now compiles in 0.94 (GCC 13) and 0.93 (Clang 18) times the hand-written wiring's time, with 0.88 and 1.11 times its memory (targets 1.3× and 1.5×). Two budgets are missed on Clang 18. The scenario's extra compile time is +0.24 s with GCC and +0.63 s with Clang, +0.38 s by interleaved compiles (target +0.3 s). Its stripped binary grows by 4 KiB with GCC and by 8 KiB and 48 bytes with Clang (target 8 KB): with Clang, the six functions that libstdc++'s inline `std::atomic::wait` imports cost a page of dynamic-linking tables and 48 bytes of GOT by themselves. Both are the owner's to decide ([details](docs/benchmarks/v0.1.md#after-t114)). New macro `TRELLIS_COLD` in `<trellis/config.hpp>`.
- **Design decisions,** recorded as ADR-0001 to ADR-0014 in [`docs/adr/`](docs/adr/README.md), informed by spikes S1 to S4:
  - 0001: C++20 baseline; C++23 and C++26 features only behind `TRELLIS_HAS_*` macros.
  - 0002: a static injector and a runtime container, sharing one binding vocabulary; both ship in 1.0.
  - 0003: constructors declared explicitly, found by C++26 reflection, or deduced without macros.
  - 0004: explicit lifetimes, and a table of the request forms each lifetime allows.
  - 0005: objects live only in injectors and scopes, and are destroyed in reverse order of construction.
  - 0006: one hard error per mistake, naming a stable `TRL-` ID, the type, the path and a fix.
  - 0007: domain classes never need to include Trellis.
  - 0008: header-only and standard library only; a single header and a C++20 module; works without exceptions or RTTI.
  - 0009: runtime errors as `result<T>`, an exception or an error handler; never `exit()`.
  - 0010: composition through variadic modules, never fluent type accumulation.
  - 0011: type identity in the runtime engine as a policy: address, name or RTTI.
  - 0012: thread-safe lazy singletons by default, an eager mode, and re-entrant construction reported in every build.
  - 0013: governance and release discipline.
  - 0014: resolution memoized per key, request form and consumer lifetime; how dependency cycles are reported in deduced mode.
- **Documentation:** the error catalog in [`docs/errors/`](docs/errors/README.md), with a check that every error ID used in `include/` has a page; maintainer notes and the doc-comment convention for public headers in [`docs/internals/`](docs/internals/README.md); and this changelog.

### Fixed

- **MSVC,** found by the first macOS and Windows CI run since Phase 1 code landed: deduced discovery failed to compile for a class whose constructor has one parameter (C3546), and refused with TRL-E004 an aggregate with a member of aggregate class type, such as `std::array` or an empty struct, as if it had an array member. `.to_ref()` of a temporary is now one error there, the deleted function, rather than two.
- **`trellis::type_name`** names member pointer types such as `int app::widget::*` the same on MSVC and Clang 21 as on GCC: MSVC left out the space before the class, and Clang 21, Apple clang 21 included, the class's namespace.
- **Compile-fail tests in parallel:** each compile runs in a scratch directory of its own. On MSVC, parallel compiles in one directory failed with C1041 on its shared `vc140.pdb`, which made most compile-fail tests fail, and a snippet that compiles pass.
